# 账单与走势图域经验

> 账单列表排序、走势图交互、明细合计口径。

---

## 账单列表排序：分桶 + 桶内排序

- **性质**: 约定
- **背景**: 原 `buildLedger` 末尾按 `period` 倒序 + 同期次 `id` 倒序，无分桶语义。用户要求未还清在前、历史在后。
- **内容**: `buildLedger` 排序段改为分桶：`bucketA = { r | r.paidStatus !== 'paid' }`（未还清，含占位行 `missing=true` / `paidStatus=null`）按 `dueDate` 升序；`bucketB` = 剩余已还账单按 `dueDate` 降序。结果 = `bucketA ++ bucketB`。分页 `slice(start, start+pageSize)` 语义不变，桶顺序在分页切页时保持稳定。

## 走势图：`@ant-design/plots` 现成折线

- **性质**: 约定
- **背景**: 原走势图 SVG 折线用原生 `<title>` 子元素做提示，延迟约 1 秒才出现，体验差。用户决策废除纯 SVG 自绘方案，改用 Ant Design 系列现成图表组件。
- **内容**: 走势图使用 `@ant-design/plots` 统计图分包的现成 `Line` 折线组件。**不安装** `@ant-design/charts` 全家桶（含关系图，避免带上用不到的依赖）。删除自绘 SVG 折线段、SVG `<title>` 子元素、自绘 HTML overlay 浮层段。tooltip 由 `Line` 组件内置承担，悬停立刻显示期次、金额、笔数。尺寸：账单页全宽高 120px 可切换月份（6/12/24/60），首页嵌入约 80px 固定 `months=6` 不提供切换。AGENTS.md 须同步删除「纯 SVG 图表、无外部图表依赖」约束。

## 去掉净入账统计

- **性质**: 约定
- **背景**: 原账单明细底部 summary 行输出「净入账 ¥X」，但偿还上一期的金额不属于本期入账，该统计无业务意义。
- **内容**: 明细表 `<Table>` `summary` 行移除金额合计单元。保留「共 N 笔」与「含年费」Tag。不输出任何金额合计行。

## 未取得账单占位行：单期生成 + 注销卡不生成

- **性质**: 约定
- **背景**: 原 `buildLedger` 从最早历史账单期循环到当前月，批量生成中间每月占位行。用户决策只为上一期已过出账日所在账期生成一期，不得按日历月、不得补中间月。
- **内容**: `buildLedger` 只为**上一期已过出账日所在账期**生成一期未取得账单占位行（`missing=true`）。出账日尚未到达的下一期**不生成**。**不得**按日历月循环。**不得**从最早历史账单补中间每个月。**注销卡不生成**占位行。判定依据为卡的出账日/还款规则推算上一期出账日是否已过，且该期无真实账单。占位行 `id=null`，不入库。

## 过期 30 天整期消失：五入口同步移除

- **性质**: 约定
- **背景**: 原实现中过期占位行可能只从账单列表隐藏而其他入口（待办、提醒）仍催。用户决策过了规则推算还款日 30 天后整期当没发生。
- **内容**: 占位行若 `now > 规则推算还款日 + 30 天`，整期不返回，就当没有这期账单。**账单列表、卡片本期应还、首页待办、未来 14 天、提醒推送**全部不再出现该期。在 `buildLedger` 返回前过滤，下游按台账行渲染自然消失。提醒引擎无该期行则不推该期。**不计入逾期**，**不计入无需还款**。占位行 `id=null` 不入库，无需删除真实账单或手动标记账单。

## 账单记录页操作列与还款状态列分工

- **性质**: 约定
- **背景**: 原还款状态列混放按钮（真实账单与未取得账单均在该列渲染「标记还款」），操作入口分散在两列。用户决策所有操作按钮统一进操作列，还款状态列只渲染状态 Tag。
- **内容**: 还款状态列只渲染状态 Tag（`paid` → 已还清 / `partial` → 部分已还 / 其余 → 待还；未取得账单 → 「未取得账单」Tag），**不渲染任何按钮**。操作列：真实账单（`!r.missing && r.id != null`）= 明细（`r.hasDetails` 时）/ 还款 / 删除（`Popconfirm` 二次确认）/ 标记异常；未取得账单（`r.missing`）= 还款 / 标记异常。**未取得账单无删除**（占位行 `id=null` 不入库，无可删记录）。**未取得账单无明细**。用户处理未取得账单改走「还款」→ MarkPaidModal「无需还款」或「标记异常」冻结/注销卡片。

## 跨页面还款按钮文案收敛

- **性质**: 约定
- **背景**: 账单记录页操作列把「标记还款」缩为「还款」后，需明确首页待办、提醒中心、还款弹窗标题是否跟改。
- **内容**: 「还款」文案**仅**账单记录页（`Bills.tsx`）操作列使用。首页待办（`Dashboard.tsx`）、提醒中心（`Reminders.tsx`）按钮文案保持「标记已还」。`MarkPaidModal` 弹窗标题保持「标记还款 - …」。其他入口没有操作列语境，不跟改。

## 部分已还 0 元不拦

- **性质**: 约定
- **背景**: 原 `PUT /:id/paid` 校验 `paidAmount <= 0`，把已还金额为 0 也拦住。用户决策 0 元表示没有还过，不得因此拦住用户。
- **内容**: `PUT /api/bills/:id/paid` 与 `POST /api/bills/mark`（`partial` 模式）校验改为 `paidAmount < 0 || !Number.isFinite(paidAmount)` 抛 400；`paidAmount === 0` 允许通过（按 `unpaid` 处理）。应还金额尚未取得时 0 元可以保存。只拦负数与非数字。
