# 版本升级框架经验

## 完整预检先于任何迁移

- **性质**: 架构约定
- **内容**: 应用启动只根据 `installedVersion` 和 `APP_VERSION` 确定版本区间，然后对该区间全部注册迁移执行只读 `inspect`。`inspect` 是每项迁移的自定义入场条件；返回空时该迁移不进计划、不创建任务、不出现在接口或界面。禁止边检查边迁移。

## 三种迁移与全局门禁

- `silent`: 细小、确定、本地、事务性且预期必然成功；仅存在静默迁移时启动直接执行，完成后再启动同步与推送。
- `optional`: 忽略后新版本仍兼容旧数据；用户只能“现在执行/忽略迁移”。等待决策时不执行任何迁移，但正常业务、同步和推送继续。
- `required`: 新版本必须完成且需用户主动确认；不允许忽略。完整计划中存在必选迁移时，所有迁移、业务写入、邮件同步和提醒推送均等待决策。

不存在“稍后执行”。用户决定全部取得后才按版本和注册顺序执行；每个目标版本全部完成或忽略后才推进游标。游标越过后，对应迁移永久不可执行。

## 旧安装版本兜底

- 已安装系统缺少 `installedVersion` 且存在邮箱绑定时，按 `0.1.0` 进入历史迁移链。
- 缺少版本号且无邮箱绑定时，直接建立当前版本游标，不制造历史迁移提示。
