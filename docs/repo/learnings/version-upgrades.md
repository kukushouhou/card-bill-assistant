# 版本升级框架经验

## 完整预检先于任何迁移

- **性质**: 架构约定
- **内容**: 应用启动只根据 `installedVersion` 和 `APP_VERSION` 确定版本区间，然后对该区间全部注册迁移执行只读 `inspect`。`inspect` 是每项迁移的自定义入场条件；返回空时该迁移不进计划、不创建任务、不出现在接口或界面。禁止边检查边迁移。

## 三种迁移与全局门禁

- `silent`: 细小、确定、本地、事务性且预期必然成功；仅存在静默迁移时启动直接执行，完成后再启动同步与推送。
- `optional`: 忽略后新版本仍兼容旧数据；用户只能“现在执行/忽略迁移”。等待决策时不执行任何迁移，但正常业务、同步和推送继续。
- `required`: 新版本必须完成且需用户主动确认；不允许忽略。完整计划中存在必选迁移时，所有迁移、业务写入、邮件同步和提醒推送均等待决策。

不存在“稍后执行”。用户决定全部取得后才按版本和注册顺序执行；每个目标版本全部完成或忽略后才推进游标。游标越过后，对应迁移永久不可执行。

## 旧安装版本兜底

- 已安装系统缺少 `installedVersion` 且存在邮箱绑定时，按 `0.1.0` 进入历史迁移链。
- 缺少版本号且无邮箱绑定时，直接建立当前版本游标，不制造历史迁移提示。

## 升级提示文案

- 标题说清用户可见的结果；说明只保留影响范围和做决定所需的后果。户级、零账单、规则传播、迁移链和执行入口等工程术语留在开发文档中。
- 界面只展示“可选更新/必须更新”。静默项目完全不展示，包括混合计划中的静默标题、范围和说明；仅静默执行时也不弹进度或完成提示，但后台仍参与完整计划协调。删除等待期间同步正常等常识性说明，不在弹窗上下堆叠流程提示。
- 可选项目使用“执行/忽略”分段切换（Segmented），不使用圆形单选框；必选项目固定执行。底部一次“确认并继续”统一提交所有选择；切换选项不保存决定，不允许逐项“现在执行”，服务端整批校验和事务保存后统一启动。
- 选择顺序固定为左侧“忽略”、右侧“执行”；执行默认选中，以主题强调色表达推荐，不额外添加“推荐”字样或角标。选择忽略时使用中性色，不把忽略渲染为主题色主操作。
- 去掉常驻流程说明不等于省略操作后果。仅当用户选中“忽略”时，就近说明该项不修正会留下什么、后续新账单如何处理；结尾统一使用用户确定的“系统将不再提供本次迁移服务。”，不再拼接操作标题，也不能暗示本期问题永久延续。切回“执行”即收起警告，仍然统一确认一次。各可选迁移通过 `ignoreWarning` 提供业务后果，旧任务从当前注册项获得文案；失败后选择忽略继续使用该项具体说明，有已完成修改时另外说明会保留。
- 已保存计划和任务的展示文案按注册项读取当前定义；执行状态、用户决定、进度和业务数据不因文案修订而改变。
- 精简文案不能删掉用户的决策依据：动态展示实际受影响的银行、邮件或卡片范围与数量，并说明要做什么、读取什么、为什么读取。银行来自盘点结果及任务业务上下文，不能写死全部支持银行；邮件重读与只更新已有账单必须说清区别。通用框架通过注册项 `describeImpact` 生成 `summary`，前端必须展示；旧任务也从保存的上下文恢复该说明。
- 视觉验收须包含可选默认、历史修正和本期修正各自的忽略后果、必选单项、三种类型混合（静默不可见）、必选失败、可选失败后忽略及执行中，并分别覆盖桌面和手机。使用隔离的合成数据，必选验收示例不得注册为正式迁移；`web/e2e/upgrade-prompt.spec.ts` 保留场景与交互检查。标题与操作顶端对齐，范围和说明各占独立行，忽略后果使用无底色的就近提示，不再挤进正文侧栏。

## 历史邮件已删除不是迁移失败

- IMAP 返回邮件不存在或无法取得原文时，历史卡片关系迁移将对应项记为 `unchanged`，保留原账单，继续其他邮件；全部缺失仍可正常完成，不能让用户重试找不回来的邮件。
- 不存在邮件日志的明细同样跳过；存在跳过项的银行不进行旧卡孤儿清理。失败项在重试时发现邮件已删除，也应转为跳过，不保留原失败。
- 连接中断等可恢复错误仍保留失败，不能把所有读取错误一概当作邮件删除。视觉验收中的失败示例明确为连接中断，不用“邮件无法读取”笼统替代；`server/tests/card-business-relations.migration.test.ts` 通过真实读取器和迁移链验证此区别，仅替换 IMAP 传输、数据库和账单落库。
