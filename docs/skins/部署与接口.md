# 皮肤存储与接口

## 持久化

已应用的皮肤标识和版本保存在 `AppSetting` 的 `appearance.skin` 键中，不新增数据库表。明暗偏好保存在浏览器 `appearance.mode`，皮肤启动缓存保存在 `appearance.skin-cache`；其中不含业务草稿、密码或 PIN。

自定义文件默认保存到 `server/data/skins/<id>/<version>/`。可通过 `SKIN_STORAGE_DIR` 指定绝对路径；相对路径基于启动目录。内置皮肤从 `server/skins` 读取，与自定义目录分开，遵循同一格式与加载流程。

两个 Docker 编排都挂载独立的 `skin-data` 命名卷到 `/app/data/skins`，镜像为 `node` 用户预建可写目录。更新镜像和重建应用容器时保留该卷；备份时同时备份数据库和皮肤卷。若自行改用宿主机目录绑定，需保证容器内 UID 1000 可读写。

安装使用目录内暂存文件，校验完成后原子移入版本目录；失败会清理暂存内容。应用信息只指向已经安装并验证的版本。当前资源丢失时读接口回退可用默认皮肤，损坏的自定义包仍在管理列表提供删除入口。

## HTTP 接口

| 接口 | 说明 |
|---|---|
| `GET /api/skins/active` | 当前可用皮肤描述，公开只读、禁止缓存 |
| `GET /api/skins/builtins` | 安装向导可选内置皮肤，公开只读 |
| `GET /api/skins/assets/:id/:version/*asset` | 按版本隔离的图片、字体和编译后 CSS；公开只读 |
| `GET /api/skins` | 认证后获取全部已安装版本及活动描述 |
| `POST /api/skins/import` | 认证后上传原始 ZIP，`Content-Type: application/zip` |
| `PUT /api/skins/active` | 认证后保存 `{ "id": "...", "version": "..." }` |
| `GET /api/skins/:id/:version/export` | 认证后导出完整 ZIP |
| `DELETE /api/skins/:id/:version` | 认证后删除；活动版本必须传 `{ "restoreDefault": true }` |

导入响应包含 `skin` 和 `exists`。普通描述包含 `manifest`、`hash`、`builtin`、`baseUrl`；资源已损坏的已安装条目还会返回 `available: false`，不可预览、应用或导出。

`GET /api/app` 附带当前皮肤描述。`POST /api/setup/install` 接受可选 `skinId`，只能选择现有内置皮肤；安装后的认证与防重装规则不变。

## 账单中心查询

`GET /api/agenda` 统一承接账单中心。参数 `view=open|today|upcoming|history`；支持 `cardId`、`cardIds`（逗号分隔）、`bank`、`kind`、`q`、`period`、`page` 和 `pageSize`。卡片单选和多选不能同时提供。

- `open`：未还清账单、有效缺账单占位和未完成常规提醒。
- `today`：调用既有提醒引擎，按账单或发生记录合并通知；通知原因附在原对象。
- `upcoming`：既有规则的未来 30 天安排；未具备处理条件时不生成写入动作。
- `history`：完成记录按账期归组，`groups` 返回完整计数和分币种金额。加 `period` 后返回组内分页记录。

汇总在分页之前完成。真实账单的键为 `bill:<id>`，常规提醒和自定义账单使用发生记录键，缺账单使用卡片、账期和币种组合；不会因为来自两个提醒事件就重复计入金额。

`GET /api/transactions` 新增互斥的 `billId` 与 `scopeBillId`：前者查询具体账单全部交易（可分页），后者按来源账单的历史关联卡片限定查询。`period` 约束所属账单账期，不替换成交易日期月份。来源不存在返回 404，不退回全量查询；无来源时继续支持未出账交易。旧只读账单明细接口保留，前端入口均已切换。

## 本地验收

自动化单元与接口测试不访问业务数据库。真实浏览器验收使用 `server/scripts/ui-fixture.ts` 的合成数据与严格数据库代理，实际挂载账单中心、统一明细和皮肤接口，不启动邮件与通知调度器。

```powershell
# 终端一：启动独立示例环境（仅 127.0.0.1:4173）
cd server
node --import tsx scripts/ui-fixture.ts

# 终端二：运行浏览器回归
cd web
node node_modules/@playwright/test/cli.js test
```

浏览器测试使用本机 Edge；测试产物与隔离皮肤放在工作区 `.ui-fixture`，不进入镜像和版本库。验证结束后关闭该进程并清理隔离数据。系统缺少 Docker 时，应另外在具备 Docker 的环境验证命名卷在容器重建后的可读写性，不能将静态编排检查当作容器实测。

验收生产构建时，先在 `web` 执行构建，然后在启动示例环境的同一终端设置 `$env:UI_FIXTURE_STATIC='1'`，再运行 `server/scripts/ui-fixture.ts`。该模式直接提供 `web/dist` 和 SPA 回退，不加载开发服务器。重启沿用 `.ui-fixture/settings.json` 与 `.ui-fixture/skins`，便于核验活动版本及资源持久化；这些文件均为隔离数据。
