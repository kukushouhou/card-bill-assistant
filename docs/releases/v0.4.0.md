# v0.4.0

- 发布日期：2026-09-05
- 对比版本：v0.3.2
- 完整差异：[v0.3.2...v0.4.0](https://github.com/kukushouhou/card-bill-assistant/compare/v0.3.2...v0.4.0)

## 版本概述

`v0.4.0` 把原本分散的账单列表、交易明细和提醒中心收敛为统一的「账单中心」，并引入完整的皮肤包系统。信用卡账单、固定账单、动态账单与常规提醒现在共用一个入口，还款、出账和年费提醒也在同一结果流中查看；真实信用卡账单可以进入统一的交易明细页，在本账单与相关卡片历史之间切换。电脑端与手机端分别设计交互，内置「克制现代」与「温润账本」两套皮肤，均提供桌面／手机 × 浅色／深色四种效果，并支持导入、预览、应用、更新、导出和删除自定义皮肤包。

本版本同时完成首页统计口径调整与 Bark 高级通知设置：首页统计卡改为「当前待还」，聚合全量未还清账单（含逾期、占位行和自定义账单）；Bark 渠道新增推送分组、通知铃声、通知级别和图标等高级配置。

## 详细变更

### 1. 账单中心统一入口

- 原「账单」与「提醒」两个入口合并为「账单中心」，`reminders` 路由重定向到账单中心「今日应提醒」视图。
- 待处理、今日应提醒、未来 30 天与历史四个查看范围共用统一记录流，按到期日期排列、逾期优先。
- 信用卡账单逐笔显示卡片身份；合并账单只出现一次，只统计一次金额，涉及的卡尾单独列出。
- 已还清账单按账期归组，显示完整账期的笔数和分币种合计；同月尚未还清的账单继续逐笔显示。
- 汇总在分页之前完成，不同币种分别汇总，未取得账单与金额待填写单独标明；常规提醒、出账提醒和年费提醒不计入待还金额。
- 提醒的新增、编辑、停用和删除集中在「提醒设置」，到期记录统一回到账单中心处理。

### 2. 统一交易明细

- 账单中心、卡片详情和首页年费入口共用明细页，即使账单暂无明细也可以进入并查看历史。
- 「本账单」查看该账单全部交易，跨自然月份或缺少交易日期的明细也保留；「历史明细」默认限定为该账单涉及的卡片，可按账期查询。
- 「查看全部明细」进入全局查询，支持按银行、卡片、交易日期及交易描述检索。
- `GET /api/transactions` 新增互斥的 `billId` 与 `scopeBillId` 查询参数，来源账单不存在时返回 404，不再退回全量查询。
- 返回时保留来源的筛选、分页、滚动和展开状态；还款、删除等操作独立触发，不会误跳进明细页。
- 旧的只读账单明细接口保留，前端入口均已切换。

### 3. 完整皮肤包与明暗模式

- 系统设置新增「外观与皮肤」，提供皮肤包管理；内置 **克制现代** 与 **温润账本** 两套皮肤。
- 每套皮肤均提供电脑浅色、电脑深色、手机浅色、手机深色四种效果，可定制背景材质、字体图形、组件排版、图表配色与明暗模式。
- 支持导入 ZIP 包、隔离预览、应用、更新、导出、删除和恢复默认；导入与预览不改变正在使用的皮肤。
- 皮肤选择跨设备同步，浅色／深色／跟随系统偏好按浏览器独立保存；换肤保留当前页面、表单和正在进行的操作。
- 皮肤包通过样式文件与素材定制，保持功能入口、操作含义和必要信息一致；内置标识 `modern`、`warm-ledger` 不允许被自定义皮肤覆盖或删除。
- 新增皮肤相关接口：`GET /api/skins/active`、`GET /api/skins/builtins`、`GET /api/skins`、`POST /api/skins/import`、`PUT /api/skins/active`、`GET /api/skins/:id/:version/export`、`DELETE /api/skins/:id/:version` 等。
- 安装向导可选内置皮肤，`GET /api/app` 附带当前皮肤描述；自定义皮肤文件持久化到 `server/data/skins`，Docker 环境映射到独立 `skin-data` 卷。
- 提供可直接安装的[石墨账本示例包](./docs/skins/examples/graphite-notebook.zip)，制作方法见[皮肤制作规范](./docs/skins/制作规范.md)。

### 4. 首页统计与待办调整

- 首页统计卡标题改为「当前待还」，聚合口径切换为全量未还清账单（含逾期、占位行和自定义账单）。
- 「当前待还」支持多币种独立金额项，计数和单位分级，金额待填写成为独立状态行。
- 今日待办的身份、状态、金额、还款日期增加明确间隔，逾期优先、已还不进待办。
- 首页各分区保持独立加载、独立报错、独立重试；标记已还同步刷新统计、待办和未来 14 天。

### 5. Bark 高级通知设置

- Bark 渠道新增自定义推送分组、通知铃声、通知级别和图标。
- 设置页可直接用尚未保存的当前配置发送测试通知。
- 通知渠道切换前会提醒处理尚未保存的修改；通知配置继续加密保存。

### 6. 电脑与手机交互重构

- 电脑端使用宽屏表格、卡片网格与分区表单；手机端使用「首页／卡片／账单／更多」底部导航、全屏业务流程和触控筛选面板。
- 移除旧的独立账单明细视图、手机明细展开页和独立提醒列表。
- 日期显示按上海业务惯例省略当年年份（当年「8月」，历史「2025年8月」）；跨年日期明确年份。
- 编辑和提交失败时保留输入，退出未保存表单时确认，连续点击不会重复提交；刷新失败保留已有内容，返回列表恢复原来的查看位置。

### 7. 部署与文档

- 两套 Docker 编排均新增 `skin-data` 卷并挂载到 `/app/data/skins`，镜像预建可由运行用户写入的皮肤目录。
- `Dockerfile` 前端构建目录调整，并预建皮肤持久目录；新增 `SKIN_STORAGE_DIR` 环境变量。
- README、部署指南、AI 部署提示词同步更新到 `v0.4.0`，界面截图与功能介绍重写为当前源码版本。

## 升级说明

- 从 `v0.3.2` 升级时，必须保留原有 `.env`、`ENCRYPTION_KEY`、数据库和 Docker 数据卷。
- 本版本**不包含数据库结构迁移**，无需清库、全量重拉或手动执行数据修复脚本；容器启动时的 `prisma migrate deploy` 无待执行变更。
- 新增皮肤数据持久化到独立的 `skin-data` 卷，不会影响既有 `db-data` 卷；备份时建议同时备份数据库和皮肤卷。
- 升级方式：内置 MySQL 执行 `docker compose pull` 后 `docker compose up -d`；外置 MySQL 使用 `docker-compose.external.yml` 执行相同流程。需要将 `.env` 中 `APP_VERSION` 改为 `0.4.0`。
- 本版本不改变 PIN、卡信息加密、邮件同步去重或还款写入规则；原有账单、金额、日期、来源邮件和还款状态全部保留。

## 已知限制

- 皮肤只能定制外观，不能改变金额含义、卡片归属、入口、操作流程或安全验证，也不包含业务脚本。
- 本机未安装 Docker 时，容器构建与命名卷实测依赖远端 CI，不能以静态编排检查替代容器实测。
- 生产构建仍提示趋势图分包超过配置的体积阈值；构建成功，继续使用 `@ant-design/plots`，未增加 charts 全家桶。
- `v0.3.2` 已说明的邮件模板识别、上游依赖、浦发账单明细、招商银行未出账明细和 HTTP 传输边界仍然适用；本版本没有新增邮件模板支持范围或外部通知渠道。
