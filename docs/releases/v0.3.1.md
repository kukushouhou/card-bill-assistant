# v0.3.1

- 发布日期：2026-09-01
- 对比版本：v0.3.0
- 完整差异：[v0.3.0...v0.3.1](https://github.com/kukushouhou/card-bill-assistant/compare/v0.3.0...v0.3.1)

## 版本概述

`v0.3.1` 修正了主卡、副卡和附属卡上线后出现的归组与界面表达问题。系统现在只会把确实包含副卡或附属卡的卡组视为银行明确的业务关系；没有子卡的主卡仍会按照原有账期规则参与普通套卡归组，不再被错误拆成单卡。

卡片中心不再显示“主卡”“副卡”“附属卡”袖标。身份袖标只会出现在明确业务组的展开详情中，普通套卡和单卡不会显示无意义的业务身份。普通套卡用于选择列表封面的操作统一改为“设为优先展示”，避免与银行确定且不可更换的业务主卡混淆。

## 详细变更

### 1. 修正业务组与普通套卡归组

- 只有业务主卡确实拥有归属于它的副卡或附属卡时，系统才会优先锁定明确业务组。
- 没有子卡的主卡继续按银行、出账日和还款规则参与普通套卡归组，并沿用原有封面优先级。
- 明确业务组继续固定使用账单确定的业务主卡，普通套卡仍允许用户调整列表中的优先展示卡。
- 服务端封面重算与前端业务组判断使用相同条件，避免列表、弹窗和操作权限出现不同结论。

### 2. 收敛身份袖标的显示范围

- 卡片中心的单卡、普通套卡封面和明确业务组封面均不显示身份袖标。
- 桌面端只在明确业务组弹窗内显示主卡、副卡或附属卡身份；移动端只在对应业务组详情中显示。
- 普通套卡弹窗和没有子卡的主卡不显示身份袖标。
- 袖标增加卡片圆角范围内的裁切，避免遮挡银行名称、设置入口或卡号。

### 3. 区分业务主卡与列表优先展示

- 普通套卡原“设为主卡”统一改为“设为优先展示”，确认文案、成功提示、移动端操作和接口错误提示同步更新。
- 明确业务组中的主卡、副卡和附属卡均不提供“设为优先展示”，用户不能改变银行账单确定的业务关系。
- 业务组标题根据实际成员显示“主卡与副卡”“主卡与附属卡”或“主卡、副卡与附属卡”；普通套卡继续显示“同一账期 N 张卡”。

### 4. 增加回归覆盖与发布技能

- 服务端测试覆盖真实业务组优先归组、孤立主卡继续组成普通套卡，以及两类卡组的封面选择差异。
- Web 测试覆盖卡片中心隐藏袖标、业务组详情显示袖标、普通套卡标题和列表封面选择规则。
- 项目新增仓库级公开发布技能，后续版本发布会自动检查完整中文更新日志、版本同步、远端 CI、GitHub Release 和多架构镜像。

## 升级说明

- 从 `v0.3.0` 升级时，保留原有 `.env`、`ENCRYPTION_KEY`、数据库和 Docker 数据卷，仅将 `APP_VERSION` 改为 `0.3.1` 后重新拉取并启动容器。
- 内置 MySQL：执行 `docker compose pull`，然后执行 `docker compose up -d`。
- 外置 MySQL：执行 `docker compose -f docker-compose.external.yml pull`，然后执行 `docker compose -f docker-compose.external.yml up -d`。
- 本版本没有新增数据库迁移，不会重新解析历史邮件，也不会修改已有账单、交易或主副卡关系数据。
- 升级过程中不得更换 `ENCRYPTION_KEY`；否则已经保存的完整卡号、有效期和 CVV 将无法解密。

## Docker 镜像

- 固定版本：`ghcr.io/kukushouhou/card-bill-assistant:0.3.1`
- 同步标签：`ghcr.io/kukushouhou/card-bill-assistant:0.3`、`ghcr.io/kukushouhou/card-bill-assistant:latest`
- 支持平台：`linux/amd64`、`linux/arm64`
- 内置 MySQL：使用 `docker-compose.yml`
- 外置 MySQL：使用 `docker-compose.external.yml`

生产环境建议固定使用 `0.3.1`，不要长期跟随 `latest`。升级时必须保留数据库、数据卷和原有 `ENCRYPTION_KEY`。

## 已知限制

- 主卡、副卡和附属卡关系仍只在银行账单明确提供证据时建立；普通多卡尾或合并账单不会自动推断业务关系。
- 普通套卡中的“设为优先展示”只改变卡片中心封面，不会改变账单归属或银行业务关系。
- 本版本没有新增功能限制。`v0.3.0` 已说明的邮件模板识别、上游依赖、浦发账单明细、招商银行未出账明细和 HTTP 传输边界仍然适用。
