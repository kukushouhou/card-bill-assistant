# v0.5.0

- 发布日期：2026-09-09
- 上一版本：v0.4.2

## 版本概述

本版本修复多家银行的账单金额、最低还款、币种和明细遗漏，并提供面向已有安装的正式升级修复流程。系统顶部和设置页现在显示运行版本，设置页增加系统介绍、GitHub 项目入口和检查更新入口。

## 详细变更

### 账单和交易明细

- 农业银行：正确转换“欠款为负”的应还与最低还款；兼容描述换行、描述内日期及空卡尾，补全遗漏交易。
- 中信银行：正确读取账户余额及最低还款列，兼容旧模板的 RMB；利用交易明细中的四位卡尾恢复旧版因三位抬头遗漏的账单。
- 北京、长沙、湖南农信：按 HTML 实际单元格或完整文本记录读取明细，兼容连续排版。
- 邮储、交通、华夏、兴业：兼容旧日期写法、单独出现的还款或消费区、跨行描述及原币／入账金额。
- 建设银行：识别带“扫码”后缀的卡尾，保留旧卡交易。无法分配给单张应还账单的交易作为同封邮件的账户共享明细，只存一份，显示真实卡尾，不计入单卡应还金额，也不属于未出账交易。
- 中国银行：依据 PDF 存入／支出列判断交易方向，避免把汇率误作金额；分别读取人民币和外币账单，兼容同一卡行同时包含两种币种。
- 光大银行：修复旧模板币种区块串读和全角美元符号识别，清除错误复制到美元账单的人民币明细；按实际金额列读取，避免将分期说明中的数字计入交易。
- 广发银行：读取同一汇总单元格内的多个卡尾，补全各卡明细；原文未声明主副卡时不推断业务身份。
- 原文交易区块出现无法解释的记录时明确报错；重新读取真实账单时保留已有还款决定。

### 升级与系统信息

- 0.5.0 必选迁移在启动时只读盘点；只有实际存在候选账单时才出现提示，显示对应银行、现有账单数与邮件数。
- 用户确认前暂停业务写入、邮件同步和提醒推送；每封邮件的数据变更与完成标记在同一事务提交，支持失败重试和重启恢复。
- 修复历史金额、最低还款、币种、明细及相关自动派生信息，保留已有账单 ID、手动还款和卡片手动设置。
- 最近升级结果列出实际修正、补建、明细变更、最低还款回退及未补齐数量。
- 顶部系统名后显示版本尾缀；设置页底部的“关于本系统”以标识、名称、简介、版本、项目与许可证链接展示，与顶部共用后端运行版本。
- “检查更新”直接打开 [GitHub 发布页](https://github.com/kukushouhou/card-bill-assistant/releases)。

### 通知与安全

- 通知设置支持多个独立渠道实例，可添加多份同类型配置，并分别命名、启停、编辑、删除和测试；安装向导同步支持多渠道，返回步骤和失败重试保留草稿。
- 桌面以列表管理渠道、分区编辑配置，手机使用卡片和独立编辑流程；高级设置默认折叠。Bark 支持搜索 32 个内置铃声，以及使用手机已经导入的铃声。
- 旧渠道保留发送身份与历史去重记录；新增渠道独立发送和重试，单份损坏配置不会阻断其他渠道。
- 标准通知渠道核对服务端的发送确认，避免把无效响应当成成功；限制响应大小并对连接错误、配置与令牌进行脱敏。
- 登录增加失败次数限制和渐进式安全验证；修改密码使旧会话失效，退出撤销当前凭证。新密码按 UTF-8 字节限制，避免长密码被截断。
- PIN 校验、换钥、销毁与敏感卡信息读写共用事务锁；进入浏览器返回缓存前清除卡片明文和 PIN，返回后重新验证。
- 私有接口禁止缓存，拦截跨站写入，增加页面防嵌套等响应头；无效 JSON 请求不会将正文带入错误日志。
- 原邮件读取限制为 32 MiB，超限明确报错且不截断入账；释放 PDF 加载资源，修复畸形 HTML 输入的重复扫描。
- 数据库驱动正确接收已配置的 TLS 参数，证书验证失败不会回退到明文；更新相关依赖和锁文件，移除部署示例中的可直接使用默认口令与密钥。

### 账单界面与配套文档

- 账单和待办列表增加清晰的明细入口、到期状态与“已还最低”展示；没有当前账单的卡片可进入已有历史明细，返回时保留来源页面状态。
- 本账单明细页展示真实应还金额、还款状态、最低还款和日期，不用当前页交易合计替代账单金额。
- 升级选择改为整批确认，按实际银行展示范围，并明确可选项目被忽略后的影响；静默项目继续不展示弹窗。
- 更新两套主题预览、README 截图、通知渠道验收与安全审计记录，补充对应的组件和浏览器回归用例。

## 升级说明

1. 保留原数据库、数据卷、`.env`、`ENCRYPTION_KEY` 和邮箱绑定。升级前保存数据库备份。
2. 将镜像版本固定为 `0.5.0` 并更新容器。启动入口先执行 Prisma 迁移，再盘点应用数据迁移；本版本包含通知渠道实例化和账户共享明细两项结构迁移。旧通知配置、启用状态和发送日志保留，不因升级重复发送。
3. 根据升级提示确认修复。没有对应历史账单的安装不触发该任务；正常账单不会因为仅有银行卡档案而进入提示。
4. 金额和明细修复覆盖全部受影响历史。自动结清状态仅从首次执行日期往前一个日历月起恢复，包含下限当天及未来账单；月末按上个月实际末日截断，重试不移动窗口。更早的还款状态、时间和已还金额保留，明确的手动还款也保留。
5. 原文无法取得时，仅修复可以可靠反推的字段；中信最低还款按修正后的应还总额恢复。不能补全的明细保留原状并显示结果；无法可靠恢复金额或写入失败时保持任务失败，可重试。
6. 不清库、不定向删卡重拉，不恢复主动删除的普通账单。新增账单仅限已确认旧解析器遗漏的币种或三位中信卡尾。
7. 升级游标越过 0.5.0 后不重复执行该迁移；不能直接降级旧程序继续使用已经迁移的数据库，回退需要匹配的数据库备份。

内置数据库编排现在要求显式填写数据库密码。如果旧部署使用过默认值，应填入与现有数据库一致的密码；只修改 `.env` 不会改变已初始化数据卷中的数据库密码。前后端需要同批更新，升级前已打开的登录页面应刷新。通知渠道管理接口改为按实例编号操作，直接调用旧类型路径的脚本需要相应调整。

招行每日信用管家继续只进入当前账期未出账明细，不因本次升级补抓历史日度交易。邮件和 PDF 原文、PDF 坐标均不入库。

## 已知限制

- 银行原邮件本身没有提供明细时，系统无法补出交易；原文已删除或邮箱不可访问时，也无法凭账单金额推测明细。
- PDF 明细借贷方向依赖原附件的表格位置，仅粘贴扁平 PDF 文本无法代替附件解析。
- 修复范围和验证结论基于已取得的模板样本，后续银行模板变化仍需要校准解析器。
- HTTPS、数据库最小权限及可信证书仍由实际部署配置负责；代理后的来源限流、多实例部署和出站网络隔离需要结合环境验证。
- 皮肤资源仍按完整包读取和校验，资源消耗压力测试与按资源读取优化尚未完成；邮件模板匹配也不能代替邮件真实性验证。详见本版本附带的安全审计记录。
