# v0.7.1

- 发布状态：补丁已准备，尚未正式发布
- 上一版本：v0.7.0
- 完整差异：[v0.7.0...v0.7.1](https://github.com/kukushouhou/card-bill-assistant/compare/v0.7.0...v0.7.1)

## 版本概述

修正附属卡历史关联恢复过程中可能使用旧任务记录的问题，并为已经升级到 0.7.0 的用户提供新的可选修复。关联正确的用户不会再次收到这项迁移提示。

## 详细变更

- 新增 0.7.1 附属卡关联修复：仅在存在可恢复的缺失关联，或旧迁移记录与历史账单能确认错误关联时，才显示「修复附属卡与主卡的关联」。
- 已经正确关联的卡保持现状，用户单独调整的正常账期规则不会被当作关联错误。
- 执行修复前，在每张卡的事务中重新检查最新有效账单和承接卡规则；关联已被其他流程更新时保留新关系。
- 尚未结束的 0.7.0 附属卡迁移由新迁移接替，只显示 0.7.1 的这一项修复；其他迁移已经确认的决定和处理进度保留。
- 修复完成后重复执行不会重写卡片，失败重试只处理未完成的明细。

## 升级说明

1. 升级前备份数据库，保留原有 `.env` 与加密密钥。
2. 正式发布后，将镜像版本更新为 `0.7.1`，拉取镜像并重新启动容器。
3. 系统先检查当前卡片。关联正确时直接完成版本升级，不弹出这项迁移；存在可修复问题时显示新的可选修复，可以选择现在执行或忽略。
4. 已经完成或忽略过 0.7.0 迁移的用户无需重置版本号或清理旧任务。0.7.1 会独立检查是否仍有可修复问题。
5. 本次没有数据库结构变更，无需重读邮件，历史账单不会被删除或重新挂载。

## 已知限制

- 为避免改变已经正确建立的关系，已有非空关联只有在旧任务快照仍匹配当前关系，且旧任务执行前的未改写账单能证明错误时才进入修复。历史证据缺失、账单后来改写或关系已由后续账单重新确认时，保留当前关系。
- 迁移后的新账单不会单独被用作认定旧迁移错误的依据。
- 并发修改与重试行为已通过受控单元测试验证；尚未进行真实 MySQL 多连接并发测试或真实邮箱联调。
