# v0.4.1

- 发布日期：2026-09-06
- 对比版本：v0.4.0
- 完整差异：[v0.4.0...v0.4.1](https://github.com/kukushouhou/card-bill-assistant/compare/v0.4.0...v0.4.1)

## 版本概述

`v0.4.1` 解决多卡一户银行的账单状态误报问题。招商、民生、平安、华夏等银行按「户」发账单：本期账单到达后，同户其他卡必然无账单，而此前系统只能把它们标为「未取得账单」，虚增当前待还数量并可能触发误导性提醒。本版本为这类银行引入「户级账单」设定：同户账单到达后，未出现在账单上的卡自动落「无需还款」零账单，户内出账日与还款规则随最新账单统一同步；真实账单后续到达时自动回正，真实数据始终优先。

本版本同时随附电脑端界面视觉与桌面布局修正，以及对应的桌面布局专项 E2E 测试与文档更新。

## 详细变更

### 1. 户级账单自动零账单

- 解析器新增账单归户模式声明：招商（全部账单解析器）、民生、平安、华夏声明为多卡一户；未声明的银行保持原有单卡单户行为，完全不受影响。
- 同户判定依据银行与持卡人归属：主卡、副卡与独立卡按自身持卡人姓名判定，附属卡按其关联主卡的持卡人姓名归户；任一侧归属不明时保守跳过，宁可维持「未取得账单」也不误判。
- 本期账单未覆盖的同户活跃卡自动生成「无需还款」零账单：金额 0、已结清，账单期次、出账日、还款日与币种与该户真实账单完全一致；该期已有账单（含手动标记）的卡不受影响。
- 户内出账日与还款规则以最新账单为准统一同步——多卡一户银行不支持按卡设置账期，账单变动全户生效；单卡单户银行的每卡独立规则不变。
- 真实账单后续到达时自动回正：零账单被真实金额与日期接管，当期账单恢复未还状态，历史账单按规则自动已还，不会出现真实账单被误标已还。
- 展示与统计口径：账单中心与卡片「本期应还」显示绿色「无需还款」标签；零账单不计入当前待还数量、今日待办、未来 14 天与 Bark 还款催缴，不进入账单走势笔数；出账提醒对 0 元账单播报「本期无需还款」。

### 2. 升级迁移（可选）

- 新增可选迁移「补齐户级账单银行当前账期零账单」：升级面板确认执行后，立即为当前待还账期内已有同户账单、自身无账单的卡补零账单并同步户内规则；也可以选择忽略，随下一期账单同步自然生效。
- 仅处理当前待还账期，不回填历史账期；需要历史数据时走既有的定向重置与历史重拉流程，零账单会随卡片档案自动重建。

### 3. 界面与布局修正（随附提交）

- 电脑端多页面视觉与桌面布局修正：首页、账单中心、设置、解析中心、邮箱、交易明细等页面的布局与样式优化，账单中心样式增强。
- 新增桌面布局专项 E2E 测试并更新既有 E2E 用例；功能文档与界面截图同步更新。

## 升级说明

- 从 `v0.4.0` 升级时，保留原有 `.env`、`ENCRYPTION_KEY`、数据库和 Docker 数据卷；需要将 `.env` 中 `APP_VERSION` 改为 `0.4.1`。
- 本版本**不包含数据库结构迁移**，无需清库、全量重拉或手动执行数据修复脚本；容器启动时的 `prisma migrate deploy` 无待执行变更。
- 新增的应用数据迁移为可选迁移，等待确认期间邮件同步、推送等业务正常运行；执行或忽略都不影响既有账单、还款状态和手动标记。
- 本版本不改变 PIN、卡信息加密、邮件同步去重或还款写入规则。
- 回滚：将镜像回退到 `0.4.0` 即可。已生成的零账单是普通账单记录，回滚后按已结清账单正常展示，不影响原有数据。

## 已知限制

- 浦发银行为按户发账单、无逐卡账单语义，不启用户级零账单机制；单卡单户银行行为与本版本之前完全一致。
- 附属卡尚未与主卡建立关联时无法参与户级归户，保持「未取得账单」现状，关联建立后自动生效。
- 零账单只对启用后新同步的账单及当前待还账期生效，历史账期不补建；需要历史数据时使用定向重置与历史重拉流程。
- 本机未安装 Docker 时，容器构建与命名卷实测依赖远端 CI，不能以静态编排检查替代容器实测。
- 生产构建仍提示趋势图分包超过配置的体积阈值；构建成功，继续使用 `@ant-design/plots`，未增加 charts 全家桶。
- `v0.4.0` 已说明的邮件模板识别、上游依赖、浦发账单明细、招商银行未出账明细和 HTTP 传输边界仍然适用。
