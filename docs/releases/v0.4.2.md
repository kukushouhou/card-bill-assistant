# v0.4.2

- 发布日期：2026-09-06
- 对比版本：v0.4.1
- 完整差异：[v0.4.1...v0.4.2](https://github.com/kukushouhou/card-bill-assistant/compare/v0.4.1...v0.4.2)

## 版本概述

`v0.4.2` 完成外观主题体验收尾：安装向导新增独立的「外观主题」步骤，部署前即可选择皮肤与明暗模式；两套内置皮肤的预览图从矢量占位图换成真实页面的实际截图，并在皮肤包中按内容哈希命名管理。同时更新皮肤选择器交互与样式、界面截图与皮肤制作文档，并补充对应的组件测试与 E2E 用例。

本版本同时把「发布必须包含工作区全部改动、禁止部分提交」写入发布规范与发布技能，避免发布内容不完整。

## 详细变更

### 1. 安装向导「外观主题」步骤

- 安装流程调整为：环境检查 → 账户设置 → 通知渠道 → **外观主题** → 完成；安装前即可选择内置皮肤、浅色／深色或跟随系统。
- 主题预览图随设备类型与明暗选择实时变化；安装完成后仍可在系统设置中调整。
- 安装向导的主题选择沿用既有皮肤接口，不新增安装期配置项。

### 2. 皮肤预览与皮肤包更新

- 内置「克制现代」与「温润账本」的预览图改为真实账单页面的实际截图，替换原矢量占位图；预览文件在皮肤包内按内容哈希命名，与 `skin.json` 的资产清单同步更新。
- 新增预览与 README 截图的生成脚本（基于 Playwright 连接隔离示例服务，先做文字基线与列对齐断言再出图）。
- 皮肤选择器与皮肤相关样式微调，明暗模式切换体验保持一致。

### 3. 界面与样式

- 首页、账单中心相关的全局样式与账单中心样式继续打磨，与主题选择联动。

### 4. 测试与文档

- 新增安装向导外观主题 E2E 用例，更新账单布局与浮层 E2E、皮肤组件测试。
- README 新增外观主题步骤说明并整体更新界面截图（首页、邮箱、解析中心、卡片、交易明细、主题设置等）；皮肤制作规范与桌面专项复核文档同步更新。

### 5. 发布规范

- 发布规范与发布技能新增「工作区完整性」硬性要求：发布提交必须包含发布时工作区的全部改动，严禁部分提交；归属存疑时必须先询问用户；仅本地临时产物按惯例清理或忽略并逐项说明。

## 升级说明

- 从 `v0.4.1` 升级时，保留原有 `.env`、`ENCRYPTION_KEY`、数据库和 Docker 数据卷；需要将 `.env` 中 `APP_VERSION` 改为 `0.4.2`。
- 本版本**不包含数据库结构迁移**，无需清库、全量重拉或手动执行数据修复脚本；容器启动时的 `prisma migrate deploy` 无待执行变更。
- 皮肤预览文件随内置皮肤包更新，自定义皮肤不受影响；既有皮肤选择与明暗偏好全部保留。
- 本版本不改变 PIN、卡信息加密、邮件同步去重、账单解析与还款写入规则。
- 回滚：将镜像回退到 `0.4.1` 即可，无数据兼容性影响。

## Docker 镜像

- 固定版本：`ghcr.io/kukushouhou/card-bill-assistant:0.4.2`
- 次版本标签：`ghcr.io/kukushouhou/card-bill-assistant:0.4`
- 滚动标签：`ghcr.io/kukushouhou/card-bill-assistant:latest`
- 支持平台：`linux/amd64`、`linux/arm64`
- 内置 MySQL：使用 `docker-compose.yml`
- 外置 MySQL：使用 `docker-compose.external.yml`

生产环境建议固定使用 `0.4.2`，不要长期跟随 `latest`。

## 已知限制

- 皮肤只能定制外观，不能改变金额含义、卡片归属、入口、操作流程或安全验证，也不包含业务脚本。
- 预览生成脚本依赖 Playwright 与本机 Edge 浏览器，仅用于开发期产出素材，不参与运行时功能。
- 本机未安装 Docker 时，容器构建与命名卷实测依赖远端 CI，不能以静态编排检查替代容器实测。
- 生产构建仍提示趋势图分包超过配置的体积阈值；构建成功，继续使用 `@ant-design/plots`，未增加 charts 全家桶。
- `v0.4.0` 已说明的邮件模板识别、上游依赖、浦发账单明细、招商银行未出账明细和 HTTP 传输边界仍然适用。
