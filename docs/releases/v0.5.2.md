# v0.5.2

- 发布日期：2026-09-12
- 上一版本：v0.5.1
- 完整差异：[v0.5.1...v0.5.2](https://github.com/kukushouhou/card-bill-assistant/compare/v0.5.1...v0.5.2)

## 版本概述

本版本包含三条主线：户级账单机制覆盖到全部按户发账单的银行；新增「逾期提醒」口径设置并修复逾期一天误显示「-1 天后还款」的问题；升级迁移框架新增「新选项提醒」模式并在账单中心提供更清晰的自定义账单/提醒入口。

此前只有招商、民生、平安、华夏启用「本期账单已到而同户其他卡必然无账单」的判定；北京、长沙、湖南银行、南京、浦发同样按户发账单，却仍按单卡单户对待，同户其余卡会一直误显示「未取得账单」并产生多余提醒。本版本统一这些银行的账单归户声明，并提供可选迁移一次性补齐当前账期的账单状态。

同时，最低还款额为 0（银行明示无最低要求）或未还最低的逾期判定此前与展示混杂：逾期一天的账单在首页待办显示为「-1 天后还款」。本版本把「怎样才算逾期」交由用户在设置中选择，默认「未全额还清」——过了还款日只要没还清就按逾期提醒，彻底消除误显示。

**新增可选迁移锚点为 0.5.2。此前已完成或忽略 0.4.1 户级账单修正的用户，升级后会看到仅覆盖新增银行的任务；已经没有待补账单的安装不会弹出提示。**

## 详细变更

### 逾期提醒口径设置（新功能）

- 系统设置新增「逾期提醒」卡片：过了还款日之后按哪种口径把账单当作逾期。两种口径：「未全额还清」（默认，只要没还清应还金额就算逾期，已还最低的账单也会继续提醒）与「未还最低还款额」（已还够最低还款额的账单不算逾期，不再提醒，等同既往行为）。
- 口径在服务端逾期判定统一收口，账单列表、今日待办、仪表盘、提醒中心与交易明细上下文全部遵循；前端不自行判逾期。
- 判定为逾期的展示优先于「已还最低」蓝标；已过还款日但未逾期（已履行最低还款）的期次不再留在首页今日待办。
- 还款弹窗不再承诺「已还最低不视为逾期」，改为随口径成立的中性说明。
- 农业银行「欠款为-」栏金额按欠款额取绝对值入库：银行偶发正数印法不再产生负的应还/最低额；「最低还款额 0.00」忠实保留，其含义由口径决定。

### 修复逾期一天的错误显示

- 修复首页待办对逾期一天的账单显示「-1 天后还款」的问题：本地日历已过期但服务端未判定逾期的兜底场景不再出现负数天数。
- 根因包含解析与判定两侧：农业银行最低还款额 0.00 的账单此前被无条件豁免逾期；桌面待办标签对负数天数无防护。

### 升级迁移「新选项提醒」模式（新功能）

- 升级迁移框架在静默、可选、必选之外新增 notice（新选项提醒）：仅告知新版本新增的设置选项，不迁移数据、等待期间不阻碍任何业务。
- 弹窗内直接内嵌选项控件，用户当场选择后确认，选择值即时保存；确认与忽略都会照常推进版本游标，不再重现。
- 本次升级即通过该模式告知逾期提醒设置；未来新增单个设置项时复用同一模式。

### 账单中心入口更名

- 账单中心右上角「提醒设置」更名为「自定义账单/提醒」，弹窗标题、空态文案与移动端同步更名，与实际管理内容（固定账单、动态账单、常规提醒）一致。

### 桌面账单明细与还款操作

- 桌面端从首页、账单中心和套卡打开的账单明细共用同一主体，保留来源页面、筛选与滚动位置；本账单提供还款与调整还款，空明细也可操作。
- 明细上下文补充承接卡编号及展示尾号，合并账单按真实账单编号登记；修复还款金额输入框被底部操作遮挡的问题。

### 关于系统卡片统一

- 「关于本系统」复用设置卡片样式，桌面右侧按钮纵排、手机等宽横排，版权分行展示；移除设置页常驻的历史迁移结果入口。

### 户级账单银行补齐

- 北京银行（2026/2021 两代解析器）、长沙银行、湖南银行（含华融湘江旧域名模板）、南京银行（2026/2023 两代解析器）、浦发银行（2026/2021 两代解析器）声明为多卡一户；至此全部按户发账单的银行语义正确。
- 浦发银行账单正文不展示卡号，但账单本身即全户账单：同户其余卡在本期账单到达后属于「无需还款」，不再按单卡单户等待永不到来的独立账单。
- 同户判定沿用既有规则：银行与持卡人归属一致（附属卡按关联主卡归属），归属不明时保守跳过；户内出账日与还款规则随最新账单统一同步。
- 零账单口径不变：0 元已结清、账单期次与日期镜像本期真实账单；不计入待还统计、待办、未来 14 天与催缴，不进走势笔数；真实账单后到自动回正。

### 可选迁移（0.5.2 锚点）

- 新增可选迁移「修正新增户级账单银行的本期账单状态」：为当前待还账期内已有同户账单、自身无账单的卡补「无需还款」并同步户内规则；仅处理当前账期，不回填历史。
- 盘点只列实际受影响的银行与卡数；已补齐的安装不进入升级计划。忽略迁移说明后果且不再重复提供。
- 执行复用户级账单既有落库口径：逐卡写入、并发安全、失败可重试，已完成结果保留。

## 升级说明

1. 保留原数据库、数据卷、`.env`、加密密钥和邮箱绑定，升级前保存数据库备份。
2. 将容器镜像或 `APP_VERSION` 更新为 `0.5.2`。本版本不新增数据库结构迁移，容器启动时的 `prisma migrate deploy` 无待执行变更。
3. 升级面板可能出现两类任务：可选迁移「修正新增户级账单银行的本期账单状态」与「新选项提醒」模式的新增逾期提醒设置。前者由用户选择执行或忽略，等待期间邮件同步与提醒正常，不产生催办；后者当场选择口径即可，选择会立即保存。
4. 逾期提醒默认口径为「未全额还清」：已还最低但未结清、且已过还款日的账单开始按逾期提醒与标红展示，这是有意的行为变化。希望保留既往「还够最低即不算逾期」的用户，可在迁移弹窗中直接改为「未还最低还款额」，或之后在系统设置中调整。
5. 已完成 0.4.1 户级账单修正的安装不会重复执行旧任务；新任务只覆盖盘点出的新增银行缺口。从更早版本直接升级时，0.4.1 与 0.5.2 两个可选任务按顺序出现，第二个只处理剩余缺口。
6. 回退程序时需核对数据库版本游标与对应备份，不应将已推进游标的数据库直接交给旧程序降级运行。

## 已知限制

- 归属不明（持卡人姓名缺失且附属卡未关联主卡）的卡保守跳过，保持「未取得账单」现状；补全持卡人或关联后自动生效。
- 零账单只对启用后新同步的账单及当前待还账期生效，历史账期不补建；需要历史数据时使用定向重置与历史重拉流程。
- 湖南农信按单卡账户账单处理（账单自带真实卡尾），不属户级账单机制范围。
- 「未还最低还款额」口径下，银行明示最低还款额为 0.00 的账单不算逾期；此类账单在账单列表以「待还」展示，不产生逾期提醒。
- 银行模板、PDF、皮肤资源与部署安全的既有限制继续适用。
