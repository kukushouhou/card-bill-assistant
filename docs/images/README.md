# README 界面配图维护

所有配图来自当前生产前端与隔离示例数据，不使用真实邮箱、卡号或通知账户。

## 更新方式

1. 在 `server` 设置 `UI_FIXTURE_STATIC=1`，运行 `node --import tsx scripts/ui-fixture.ts`，启动 `127.0.0.1:4173` 隔离示例服务。
2. 在 `web` 执行 `npm run screenshots:readme`。它先构建前端，使用实际账单页面生成两套皮肤的 8 张预览；更新皮肤资源声明后再次构建，最后生成全部 README 配图。README 引用的任何界面配图未生成都会报错。
3. 同时查看原始预览和安装／管理页里的缩略图，检查金额字形、符号基线、字段起点、标题与选中状态，不只检查图片外框。
4. 结束示例服务并清理本次生成的隔离设置与临时日志。截图及对齐数据保留作为审核证据。

请勿将生成脚本指向真实应用。脚本固定使用本地隔离服务，并要求 `/__fixture` 确认后才继续。

## 本次覆盖

- 电脑：账单中心、首页、统一明细、卡片中心、邮箱、试解析结果、皮肤管理、安装主题。
- 手机：首页、账单中心、统一明细、安装主题，以及两套皮肤的浅色／深色展示。

安装主题图片显示独立的「外观主题」步骤。账单与明细采用当前组件，人民币金额不附加「人民币 / CNY」说明。

内置皮肤预览由 `web/scripts/capture-skin-previews.mjs` 生成，金额须使用齐线等宽数字，符号与数字、状态名称与数量的基线误差小于 0.5px，桌面字段和操作列起点保持一致。只有 8 种效果全部检查成功才更新预览。图片按内容摘要命名，避免浏览器继续显示缓存的旧图；皮肤包导出包含实际 PNG 文件。对齐记录保存在 `.ui-fixture/skin-preview-audit.json`。

待处理预览同时验证逾期优先、还款日升序及界面与接口的记录顺序一致。需要同时展示多种到期状态时，修改示例日期后必须按相同规则重排；不能把未排序的验收数据当作产品预览。本账单截图必须保留应还总额和还款状态。
